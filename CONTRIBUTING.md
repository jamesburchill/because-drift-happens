# Contributing

Because Drift Happens is an evolving public doctrine for coherent autonomous operations. Contributions should make the framework clearer, more precise, and more useful for people designing governable autonomous systems.

## Good Contributions

Useful contributions include:

- Clearer definitions.
- Better examples.
- Diagrams that explain concepts without oversimplifying them.
- New or refined failure patterns.
- Governance models for federated agents and autonomous workflows.
- Reading-map improvements.
- RFCs that clarify scope, terminology, or operating assumptions.
- Corrections where the language is vague, overbroad, or hard to apply.

## What To Avoid

Please avoid:

- Hype.
- Vendor promotion.
- Fear-based AI narratives.
- Broad claims without operational grounding.
- Confidential, client, personal, or commercial material.
- Product-specific implementation details unless clearly marked as conceptual examples.
- Language that presents the framework as complete or universally adopted.

## Style

Use plain language. Prefer calm architectural wording over slogans. Use Canadian English spelling. Avoid em dashes; use two hyphens if a longer pause is needed.

When introducing the concept, use the full phrase "Because Drift Happens." Use abbreviations only after the full phrase has already been defined in the same document.

## Contribution Process

1. Open an issue if the change affects terminology, scope, patterns, or governance models.
2. Use an RFC for larger conceptual changes.
3. Keep pull requests focused.
4. Explain the operational problem the change addresses.
5. Update related glossary, reading-map, or example files when terminology changes.

The goal is not volume. The goal is durable language that can help teams reason about drift, coherence, governance, and intervention in autonomous systems.
