# Reading Map

This reading path helps new readers move from premise to vocabulary to practical patterns.

## 1. Start With The Position

Read [Doctrine](doctrine.md) first. It states the stable drift and governance triplets.

## 2. Read The Manifesto

Read [Manifesto](manifesto.md) next. It states the architectural argument behind Because Drift Happens.

## 3. Learn The Operating Principles

Read [Principles](principles.md) next. These principles explain the assumptions that guide the framework.

## 4. Establish The Vocabulary

Read [Glossary](glossary.md) before going deeper. The framework depends on consistent use of terms such as drift, coherence, control plane, intervention, and runtime governance.

## 5. Understand The Core Concepts

Read these in order:

1. [Drift](drift.md)
2. [Coherence](coherence.md)
3. [Governance](governance.md)
4. [Observability](observability.md)
5. [Intervention](intervention.md)

## 6. Move To Distributed Autonomy

Read [Federation](federation.md) and [Control Planes](control-planes.md) to understand why multi-agent and distributed systems need governance above individual execution paths.

## 7. Study Failure And Design Patterns

Read [Failure Patterns](failure-patterns.md) and [Architecture Patterns](architecture-patterns.md). These documents translate the doctrine into recurring operational problems and design responses.

## 8. Review Examples And RFCs

Use [Examples](examples/index.md) for simple conceptual scenarios. Use [RFCs](rfcs/index.md) to understand scope decisions and propose changes to the framework.
